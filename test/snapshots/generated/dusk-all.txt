# app

A Dusk app: file routes, loaders, server functions and server rendering.

## Getting started

```bash
npm install
npm run dev
npx convex dev   # in a second terminal: log in, create a deployment, write VITE_CONVEX_URL
```

## Scripts

- `npm run dev` starts the development server with hot reload.
- `npm run build` builds for production.
- `npm run start` serves the production build (run `build` first).
- `npm run typecheck` type-checks with `tsc --noEmit`.
- `npm run lint` checks the code with Biome.
- `npm run format` formats the code with Biome.
- `npm run test` runs the tests once.
- `npm run test:watch` runs the tests and re-runs them on change.
- `npm run lint:eslint` checks the code with the ShadowJS ESLint rules.
- `npm run convex` runs `convex dev`.

## Project layout

- `src/routes` maps files to URLs: `index.tsx` is `/`, `posts/[id].tsx` is `/posts/:id`, `_layout.tsx` wraps its folder, `[...rest].tsx` catches everything else. A file that exports `GET`, `POST`... (`api/health.ts`) is an API route.
- `src/server` holds server-only code. A function made with `serverFn` can be called from components and loaders; in the browser it becomes a request to the server, with its input validated first.
- `src/app.tsx` is the root component, `src/entry-server.ts` sets the security options, middleware and limits of the request handler.
- `dusk build` writes the Node server (`dist/node/server.mjs`); `npm run start` (`dusk start`) runs it. Set `APP_URL` to the public address of the app.

## UI components

Components are copied into `src/components/ui` so you own them: `npx shadow-ui add button`. The theme (colors, radius, dark mode) is imported in `src/index.css`; `@/` points at `src/`. `cn()` in `src/lib/utils.ts` merges class names.

## ESLint

`npm run lint:eslint` runs the Dusk rules of `@shadow-js/eslint-plugin`. The plugin parses TypeScript and JSX itself, so it works with the TypeScript 7 this app compiles with. The `shadow/server-only-import-in-client` rule applies the same client/server boundary as the Dusk build: `*.server.ts` files and Node built-ins cannot reach the browser.

## Devtools

In development a launcher button opens the inspector; `Alt+Shift+D` toggles it. It is imported only when `import.meta.env.DEV` is true, so the production build does not contain it.

## Convex

Run `npx convex dev` in a second terminal. The first time it asks you to log in, creates a deployment, writes `VITE_CONVEX_URL` to `.env.local` and keeps `convex/_generated` up to date while you edit the functions in `convex/`.

- `convex/schema.ts` defines the tables, `convex/tasks.ts` holds a query and a mutation.
- `src/routes/tasks.tsx` lists the tasks with `useQuery` and adds one with `useMutation`.
- `convex/_generated` starts as a stand-in with the same exports, so the app type-checks and builds before the first `convex dev`; Convex replaces it.
- `convex/auth.config.ts` trusts the Clerk JWT template named `convex`: see the Clerk section.

## Clerk

1. Create an application at https://dashboard.clerk.com and copy its keys into `.env.local` (see `.env.example`).
2. Put the secret key in `CLERK_SECRET_KEY`. `src/entry-server.ts` verifies the session of every request with it and sends signed-out visitors away from `/dashboard`; the loader of the page asks the server again through `requireUser`, so client-side navigation is checked as well.
3. In the Clerk dashboard create a JWT template named `convex`, then run `npx convex env set CLERK_JWT_ISSUER_DOMAIN <the Issuer of that template>`. `convex/auth.config.ts` trusts it and `ConvexProviderWithAuth` sends the token, so `ctx.auth.getUserIdentity()` works in your functions.

import { v } from "convex/values";
import { mutation, query } from "./_generated/server";

const MAX_TITLE = 200;

export const list = query({
  args: {},
  handler: async (ctx) => {
    return await ctx.db.query("tasks").order("desc").take(50);
  },
});

export const create = mutation({
  args: { title: v.string() },
  handler: async (ctx, args) => {
    const identity = await ctx.auth.getUserIdentity();
    if (identity === null) throw new Error("Sign in to add a task.");
    const title = args.title.trim();
    if (title === "" || title.length > MAX_TITLE) {
      throw new Error("A title has 1 to 200 characters.");
    }
    return await ctx.db.insert("tasks", {
      title,
      done: false,
      ...(identity === null ? {} : { author: identity.subject }),
    });
  },
});

import { clerkMiddleware, createRouteMatcher, getAuth } from "@shadow-js/clerk/server";
import type { HandlerOptions, Middleware } from "@shadow-js/dusk/server";

const appUrl = new URL(process.env.APP_URL ?? "http://localhost:3000");
// Every page that needs a signed-in user. The matcher compares the same canonical path the router uses
// (case, percent-encoding and trailing slashes included), so `/DASHBOARD` and `/%64ashboard` are covered too.
const isProtected = createRouteMatcher(["/dashboard(.*)"]);

let authenticate: ReturnType<typeof clerkMiddleware> | undefined;

/** Verifies the Clerk session of every request. It is created on first use, so a build needs no keys. */
const withClerk: Middleware = (event, next) => {
  authenticate ??= clerkMiddleware({
    secretKey: process.env.CLERK_SECRET_KEY ?? "",
    publishableKey: import.meta.env.VITE_CLERK_PUBLISHABLE_KEY ?? "",
    authorizedParties: [appUrl.origin],
  });
  return authenticate(event, next);
};

/** Sends signed-out visitors away from the protected pages before any of their code runs. */
const protectPages: Middleware = (event, next) => {
  if (isProtected(event.request) && getAuth(event)?.isSignedIn !== true) {
    return Promise.resolve(Response.redirect(new URL("/sign-in", event.url), 302));
  }
  return next();
};

/** Options of the request handler. Everything here has a safe default; see the Dusk docs. */
export const options = {
  middleware: [withClerk, protectPages],
  security: {
    // The Host header is attacker input: production answers only for the hosts of APP_URL.
    ...(import.meta.env.PROD ? { allowedHosts: [appUrl.hostname] } : {}),
    // Sent on https responses only. CSRF checks, secure headers and body limits are on by default.
    headers: { hsts: { maxAge: 63_072_000, includeSubDomains: true } },
    // Clerk loads its scripts and talks to its API from the frontend API host of your key. Report-only until
    // you add that host to script-src, connect-src, img-src and frame-src; then drop `reportOnly` to enforce.
    ...(import.meta.env.PROD ? { csp: { reportOnly: true } } : {}),
  },
} satisfies Omit<HandlerOptions, "manifest">;

export default options;

  | string

  | bigint
  | boolean
  | null
  | undefined

/**
 * Joins class names (strings, arrays, `{ name: condition }` objects) and resolves Tailwind
 * conflicts, so the last utility wins: `cn("px-2", props.class)` lets the caller override `px-2`.
 *
 * @param inputs - Any mix of class values; falsy values are skipped.

 *
 * const active = true;
 * export const classes = cn("px-2 py-1", active && "bg-primary", "px-4");

 * ```
 * @since 1.0.0
 * @see {@link ClassValue}
 */
export function cn(...inputs: ClassValue[]): string {
  return twMerge(clsx(...(inputs as Parameters<typeof clsx>)));

import { ClerkProvider, clerkConvexAuth } from "@shadow-js/clerk";
import {
  type ConvexClientLike,
  ConvexProviderWithAuth,
  createConvexClient,
} from "@shadow-js/convex";
import { ErrorBoundary, isServer, type ParentProps } from "@shadow-js/web";
import { requireEnv } from "./lib/env";

// No socket on the server: the page is rendered once, the browser then subscribes. The stand-in
// never connects, and it keeps the provider tree the same on both sides, so hydration keys match.
const serverConvex: ConvexClientLike = {
  onUpdate: () => () => undefined,
  mutation: () => Promise.reject(new Error("Mutations run in the browser, not on the server.")),
  action: () => Promise.reject(new Error("Actions run in the browser, not on the server.")),
  setAuth: () => undefined,
};
const convex: ConvexClientLike = isServer
  ? serverConvex
  : createConvexClient(requireEnv("VITE_CONVEX_URL", import.meta.env.VITE_CONVEX_URL));
const publishableKey = requireEnv(
  "VITE_CLERK_PUBLISHABLE_KEY",
  import.meta.env.VITE_CLERK_PUBLISHABLE_KEY,
);
const loadOptions = {
  signInUrl: "/sign-in",
  signUpUrl: "/sign-up",
  signInFallbackRedirectUrl: "/dashboard",
  signUpFallbackRedirectUrl: "/dashboard",
};
// Convex asks Clerk for a token made from the JWT template named "convex".
const useConvexAuth = clerkConvexAuth({ template: "convex" });

function ConvexBridge(props: ParentProps) {
  return (
    <ConvexProviderWithAuth client={convex} useAuth={useConvexAuth}>
      {props.children}
    </ConvexProviderWithAuth>
  );
}

function clerkFailed(error: unknown, reset: () => void) {
  return (
    <div role="alert">
      <p>Clerk could not be loaded: {error instanceof Error ? error.message : String(error)}</p>
      <button type="button" onClick={reset}>
        Try again
      </button>
    </div>
  );
}

export function Providers(props: ParentProps) {
  return (
    <ErrorBoundary fallback={clerkFailed}>
      <ClerkProvider publishableKey={publishableKey} loadOptions={loadOptions}>
        <ConvexBridge>{props.children}</ConvexBridge>
      </ClerkProvider>
    </ErrorBoundary>
  );
}

import { useStore } from "@shadow-js/core";
import type { Metadata } from "@shadow-js/dusk";
import { A, useLoaderData, useRouter } from "@shadow-js/router";
import { For } from "@shadow-js/web";
import { createPost, listPosts } from "../../server/posts";

export const metadata: Metadata = { title: "Posts" };

/** Runs on the server for the first request and in the browser for later navigations. */
export const loader = () => listPosts(undefined);

export default function Posts() {
  const posts = useLoaderData<Awaited<ReturnType<typeof listPosts>>>();
  const router = useRouter();
  const [message, setMessage] = useStore("");

  async function submit(event: SubmitEvent & { currentTarget: HTMLFormElement }) {
    event.preventDefault();
    const form = event.currentTarget;
    const data = new FormData(form);
    try {
      await createPost({ title: data.get("title"), body: data.get("body") });
      form.reset();
      setMessage("");
      await router.invalidate();
    } catch (error) {
      setMessage(error instanceof Error ? error.message : "Could not save the post");
    }
  }

  return (
    <section>
      <h1 class="text-3xl font-bold">Posts</h1>
      <ul class="my-4 list-disc pl-6">
        <For each={posts() ?? []}>
          {(post) => (
            <li>
              <A to="/posts/:id" params={{ id: post.id }}>
                {post.title}
              </A>
            </li>
          )}
        </For>
      </ul>
      <form onSubmit={submit}>
        <input
          name="title"
          placeholder="Title"
          required
          class="my-2 block w-full rounded border p-2"
        />
        <textarea
          name="body"
          placeholder="Body"
          required
          class="my-2 block w-full rounded border p-2"
        />
        <button type="submit" class="rounded bg-black px-4 py-2 text-white">
          Add post
        </button>
        <p role="alert">{message()}</p>
      </form>
    </section>
  );
}

import { getAuth } from "@shadow-js/clerk/server";
import { redirect, serverFn } from "@shadow-js/dusk/server";

/**
 * Answers with the signed-in user, or redirects to the sign-in page. Loaders of protected pages
 * call it, so a client-side navigation is checked on the server too: the middleware in
 * entry-server.ts only sees full page requests.
 */
export const requireUser = serverFn({ method: "GET" }, (_input, event) => {
  const auth = getAuth(event);
  if (auth === undefined || !auth.isSignedIn || auth.userId === null) throw redirect("/sign-in");
  return { userId: auth.userId };
});

const postId = defineSchema<{ id: string }>((input) => {
  const issues: Issue[] = [];
  const id = stringField(input, "id", 32, issues);
  return issues.length > 0 ? { issues } : { value: { id } };
});

const newPost = defineSchema<{ title: string; body: string }>((input) => {
  const issues: Issue[] = [];
  const title = stringField(input, "title", 120, issues);
  const body = stringField(input, "body", 2000, issues);
  return issues.length > 0 ? { issues } : { value: { title, body } };
});

export const listPosts = serverFn({ method: "GET" }, () => readPosts());

export const getPost = serverFn({ method: "GET", input: postId }, ({ id }) => {
  const post = findPost(id);
  if (post === undefined) throw notFound();
  return post;

import type { StandardSchemaV1 } from "@shadow-js/dusk/server";

/** One problem found while validating input. */
export interface Issue {
  message: string;
  path?: string[];
}

/**
 * Builds a Standard Schema, the interface Zod, Valibot and ArkType also implement, so a server
 * function can take any of them as its `input`. This one has no dependency; swap it for a library
 * when your inputs grow.
 */
export function defineSchema<Output>(
  check: (input: unknown) => { value: Output } | { issues: Issue[] },
): StandardSchemaV1<unknown, Output> {
  return { "~standard": { version: 1, vendor: "app", validate: check } };
}

/** Reads a string field of an unknown value, trimmed, or reports why it is not usable. */
export function stringField(input: unknown, name: string, max: number, issues: Issue[]): string {
  const value: unknown =
    typeof input === "object" && input !== null ? Reflect.get(input, name) : undefined;
  if (typeof value !== "string" || value.trim() === "") {
    issues.push({ message: "Required", path: [name] });
    return "";
  }
  if (value.length > max) issues.push({ message: `At most ${max} characters`, path: [name] });
  return value.trim();
}
